==== aclspv_specid

[quote]
`aclspv_specid(specid : u32)`

[quote]
____
Make constant value modifiable on vulkan pipeline. +
See link:https://docs.vulkan.org/refpages/latest/refpages/source/VkPipelineShaderStageCreateInfo.html[shader stage create info]
____

* if `specid` is `0xFFFFFFFF`, it will be seen undefined.
* Maps to `OpSpecConstant` with id of `specid`
* Result type must be scalar Integer or Floating point type.
* Follows the first specified value & data type.
* Default value must be specified on first use.
* Ignores the initialising value when specid is found.
* Must be specified on use. E.g:
** Setting a size of an constant array
** Initialising a non-constant variable
* Specifying on following condition will be ignored
** Enumerators
** `__constant` variable
** Constant literals

++++

entry point

[quote]
____
is a void (void); with interface attached. +
you can have multiple entry points in a shader. (you can have vertex & frag shader at one go!) +
in aclang the entry point is very flexible since execution mode & objects are represented as attributes & arguments.
____

arguments

[quote]
____
unlike normal function, arguments of entry point have different meaning. +
for pointers with <<aclspv_storage_class,storage class>> will be a variable declared globally binded. +
for non-pointers will be an element appended on one push constant block. +
without `storage class` specified on pointer parameter, compiler should emit an error.
____

bindables

[quote]
____
every entry points have its own reserved <<aclspv_set,descriptor set>>, incremented from 0. +
from left to right, bindable arguments have its reserved <<aclspv_bind_idx,binding index>> from 0, incremented on every bindable obejcts.
____

== Builtin

[quote]
____
Builtin expressions recognised while carving. +
Unlike <<attributes,Attributes>>, they are not annotations: they use ordinary call syntax (or a vector expression) and are emitted as SPIR-V instructions.
____

=== __builtin_sinf / __builtin_cosf / __builtin_tanf

[quote]
____
`__builtin_sinf(x)` +
`__builtin_cosf(x)` +
`__builtin_tanf(x)`
____

* emit `GLSL.std.450` `Sin` (instruction 13), `Cos` (14), and `Tan` (15).
* scalar only: operand and result are 32-bit floating point (`f32`).
* the operand is cast to the result type before the call is emitted.
* passing a vector is a clang type error, so these spellings never yield a vector.
* a scalar literal operand is folded on the host into an `OpConstant` instead of `OpExtInst`, because an extension instruction cannot appear in `OpSpecConstantOp`.
* `f64` (`__builtin_sin`) is not supported for now.
* the bare `sinf` / `cosf` / `tanf` names are not recognised; only the `__builtin_` spellings are.
* the `GLSL.std.450` import is emitted on first use.

++++
<div class="listingblock" style="background-color:#1c171b;color:#d8ccd3;padding:0.8em 1em;overflow-x:auto;border-radius:4px">
<pre style="font-family:'Source Code Pro','DejaVu Sans Mono','Courier New',monospace;font-size:14px;line-height:1.3;margin:0;background:transparent;color:inherit"><span style="color:#d0aa68;font-weight:bold">typedef</span> <span style="color:#d0aa68;font-weight:bold">float</span> f32;

<span style="color:#d0aa68;font-weight:bold">void</span> f32_math(f32* in, f32* out) {
    *out = __builtin_sinf(*in);
    *out = __builtin_cosf(*in);
    *out = __builtin_tanf(*in);

    <span style="color:#a99ba3;font-style:italic">/** folded: no OpExtInst is emitted */</span>
    *out = __builtin_sinf(<span style="color:#d99462">0.5f</span>);
}</pre>
</div>

=== shufflevector

[quote]
`__builtin_shufflevector(v1, v2, i0, i1, ...)`

* emits `OpVectorShuffle`.
* `v1` and `v2` must be vectors of the same component type.
* the mask indexes the concatenation `v1 ++ v2`, so every `iN` must be a literal integer in `[0, 2 * |v1|)`.
* the result length is the number of mask components; it may differ from the input length.
* only `v1` and `v2` are evaluated: the mask is not part of the expression operand stream.
* the result component count must equal the mask count, as `spirv-val` requires.

++++

== Restriction

[quote]
Some statements / extensions may not be planned to be supported for now.

* `VK_KHR_relaxed_block_layout` behaviour (free alignment)
* Non plain-old-data types
* `OpenCL` memory model
* `function-scoped variable` shadowing function parameter
* designated initializer list
* pointer arithmetic on non-physical addressing model
* global variables
* pointer to struct on input | output buffer
